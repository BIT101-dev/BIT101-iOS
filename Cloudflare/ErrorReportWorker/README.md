# BIT101 错误报告 Worker

此 Worker 提供独立于 `open.aihelpme.dev` 的反馈 API；网页内容由对应网页 Worker 承载，仓库保留单一反馈 API 入口。

## 接口合同

Worker 提供 `POST https://feedback.aihelpme.dev/api/error-reports` 接口。

请求体上限按六张最大附件的完整 Base64 长度，加上 1 MiB 报告元数据空间计算。建议页最多上传 6 张图片。App 内将每张图片以约 1 MB 为目标压缩，Worker 单张上限为 2 MB，并校验 Base64 字符、填充及末尾编码位，再将图片存入 KV。文本脱敏处理报告字段和附件元数据，已校验的附件 Base64 沿原值保存。建议报告使用 `mode: "suggestion"`，与错误报告共用 KV。拉取脚本按“错误报告 / 用户建议”分目录保存，并将图片解码为独立文件。诊断记录及附件元数据按各自结构验收，异常结构与序列化失败在配额及 KV 写入前返回 400。报告文本、附件名称、类型和扩展字段共用 1 MiB 元数据预算，图片 Base64 沿独立附件预算核对，超限返回 413。

客户端与 Worker 共用受保护字段清单，脱敏覆盖完整认证头、Cookie、JSON 字符串及键值文本。URL 参数按解码后的键名核对，嵌套登录链接沿解码后的 URL 继续处理，URL 账号密码统一遮盖，fragment 含受保护内容时整段遮盖。百分号解码最多执行八轮，达到预算时整体遮盖 URL；审计自测核对双方字段清单并注入深层编码参数、fragment、嵌套链接、转义字符串和多段认证值。

## 准入与配额

UTC 日配额由 SQLite Durable Object 在事务内预留，正式报告与网络探针分别保留每日 1000 次预算，每个来源在各自预算中每日最多提交 100 次。来源采用 Cloudflare `CF-Connecting-IP` 与 UTC 日期的 SHA-256 摘要，日计数更新时替换来源集合；共享出口的请求共用来源限额。部署配置同时登记配额 binding 与存储迁移。浏览器预检返回空响应体的 204 和接口 CORS 头。

校园 NAT 与宿舍出口沿同一来源累计，维护者结合出口内用户数、实际反馈峰值及维护者处理能力评估预算。正式报告的来源限额可通过 Worker 配置的 `REPORT_SOURCE_DAILY_LIMIT` 调整，默认值为 100，有效范围为 1 至全局日预算；全局 1000 次预算与独立网络探针配额继续约束总量。配额配置异常返回 503，来源和全局预算耗尽分别返回对应的 429。配置调整与部署沿既有发布流程开展。

报告提交沿 Cloudflare 来源身份预留处理准入预算，再逐块读取正文；准入预算覆盖正式报告与网络探针预算之和，来源预算采用两类来源限额较高值的两倍，覆盖异常请求。累计字节超过请求体上限时终止读取。报告类型、业务正文、附件、邮件字段类型和网络探针标记在报告配额预留前验证；有效报告进入持久化流程。客户端核对 201 创建回执中的报告编号与本次 `requestID` 一致，并核对最终请求地址与方法后发布提交成功。

## 存储生命周期

正式报告正文与附件在 KV 保留 30 天，到期自动清理；本地收件箱继续保存已拉取内容。KV 列表索引按标题、版本和构建号的摘要长度约束在平台 1024 字节预算内，完整字段保留在正文。

建议和错误报告使用 UUID `requestID` 标识一次提交。页面在失败重试期间保留首次完整载荷，编辑内容后建立新的提交，成功后释放该次载荷。Worker 按该编号串行受理，在 30 天保留期内为相同脱敏内容返回同一 201 回执，复用首次 KV 键、正式报告配额与投递任务；每次 HTTP 请求仍消耗处理准入预算。正式配额预留身份由请求编号与内容摘要组成，与日计数在同一事务保存，跨 UTC 日期沿 30 天有效期复用；alarm 按最早到期身份清理并继续排程。同编号的内容差异返回 409，已删除记录的重试返回 410。历史客户端省略编号时由 Worker 生成报告编号。

## 邮件投递

Worker 收到新报告后会向已验证的维护者邮箱发送结构化提醒，邮件主题区分“错误报告”和“用户建议”，正文包含标题、用户补充、联系方式、版本、设备、系统、网络、诊断数量、状态码统计和最近失败请求；邮件保留报告编号与 KV 查看键，图片附件继续留在 KV 中。邮件正文使用 Worker 脱敏后的报告字段，避免发送完整原始响应和图片。运行时收件地址由 `wrangler.jsonc` 的 `REPORT_EMAIL_RECIPIENT` 变量提供，`REPORT_EMAIL` binding 限制同一地址，审计核对二者一致；修改配置后需先在 Cloudflare Email Routing 中验证，再重新部署 Worker。

每个报告的紧凑受理及投递任务由 `ReportEmailDelivery` Durable Object 保存，任务保留报告编号、内容摘要、首次 KV 键与过期清理 alarm。正文写入前先登记近期 alarm，受理状态保存完成后继续投递；正文保存后受理确认中断时，alarm 读取已保存正文并完成受理与投递。存储故障返回可重试的错误，重试沿已保存的任务定位写入，同一 201 回执还会修复缺失的投递 alarm。历史客户端的正文写入失败通过任务删除入口取消投递并清理该报告键。alarm 读取已受理且已脱敏的正文发送提醒。平台默认指数退避允许六次重试，耗尽后沿持久化失败计数重新排程，退避间隔上限为一小时，持续到报告保留期结束。投递状态保存为 `pending` 或 `sent`，发送前保存尝试次数，发送后保存消息标识与更新时间，并写回报告及列表元数据。提醒采用至少一次投递：发送成功与 `sent` 保存之间发生存储失败或进程退出时，重试可能产生重复邮件。邮件主题和 `X-BIT101-Report-ID` 头携带稳定报告编号，处理提醒时按编号归并；完整反馈以 KV 中同一报告键为准。已保存的 `sent` 状态在 KV 更新重试时复用，KV 持续故障同样沿保留期重新排程。alarm 的重试语义沿 [Cloudflare 文档](https://developers.cloudflare.com/durable-objects/api/alarms/) 维护；邮件头沿 [Email Service 合同](https://developers.cloudflare.com/email-service/reference/headers/) 设置。任务与状态在报告保留期结束时清理，任务保存报告定位信息，正文和图片继续由同一 KV 记录承载。

## 网络验收

网络冒烟会向同一接口发送 `mode: "network-smoke"` 的临时请求。Worker 沿正式记录的序列化和列表元数据结构写入、读取、核对并删除临时 KV 键，响应以 `recordVerified`、`temporaryRecordRemoved` 和 `quotaReserved` 标明正式记录结构核对、清理结果与配额预留；App 验收入口要求这三个字段，部署 Worker 后执行配套网络验收，临时键使用 120 秒有效期，读取沿最小 30 秒缓存周期等待，60 秒可见性期限结束时返回 `503 smoke_visibility_timeout`。读写阶段沿 `finally` 提交删除，`temporaryRecordRemoved` 表示删除操作已完成，缓存沿 KV 的一致性窗口收敛；App 探针为可见性阶段及传输保留 80 秒。

邮件送达由发布验收的 `feedback-delivery` 专项核对正式 App 报告、持久化存储键及维护者收件证据。

## 维护操作

在仓库根目录查看和管理报告；默认调用分页拉取开放 Issues、CI 失败与反馈，在固定收件箱累计保存正文与附件。收取与删除沿 `wrangler.jsonc` 的 `ERROR_REPORTS` 绑定读取存储 ID。同一报告键复用已有文件，投递中的报告持续刷新状态，正文或附件缺失、附件字节数或摘要发生变化时重新拉取。远端报告通过 `delete` 操作管理。报告操作共用收件箱锁。单份报告的终端输出展示正文、附件类型与字节数，图片由收件箱流程保存为独立文件：拉取脚本将历史异常 MIME 元数据的附件保留为二进制文件。

```bash
Scripts/fetch-issues-and-reports.sh list
Scripts/fetch-issues-and-reports.sh latest
Scripts/fetch-issues-and-reports.sh show <报告键>
Scripts/fetch-issues-and-reports.sh delete <报告键>
```

删除脚本沿现有 KV 编辑权限建立五分钟有效的单次授权，再调用同一 API 的 `DELETE` 操作。删除请求沿 Cloudflare 来源身份预留独立处理准入预算，正文上限为 1 KiB；删除与提交的准入计数分别保存。授权尚待 KV 可见时，在五分钟有效期内沿同一授权重试；等待和请求共用剩余期限，完成及失败均清理授权。Worker 核对授权与报告键，将删除交给该报告的投递对象；取消状态、状态回写和正文删除在对象的输入门内串行执行。已有发送请求沿邮件服务完成，后续回写和重试沿取消状态停止。授权键和本地授权文件在操作结束时清理。提交准入配额耗尽时继续核验单对象删除授权。

报告抓取在四个工作线程内完成下载、解析和落盘，任务结果返回报告键；正文内存随并发数保持有界，整批成功后提交暂存归档与已处理键。


## 部署

Worker 已绑定独立 KV 和 `feedback.aihelpme.dev`。部署前使用以下命令更新 Worker：

```bash
cd Cloudflare/EmergencyUpdateWorker
python3 ../../Scripts/validation_provenance.py deploy-worker ErrorReportWorker
```

发布新版 App 前，沿既有部署流程发布此受理合同，再完成反馈提交与邮件送达验收。
