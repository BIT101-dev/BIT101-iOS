审计范围：本地 Swift Package、App 组装、账号生命周期、网络恢复、日程持久化、成绩服务、共享快照、测试和静态检查。基准取自本轮源码审计，验证日期为 2026-09-30。

## 发现与处理

| 审计发现 | 修复后的行为 | 主要证据 |
| --- | --- | --- |
| 社区 401 重试读取变化中的账号 Cookie | 每次请求捕获账号、登录代际和凭据；发送、恢复、重放与解码核对归属，切号返回取消 | `CommunitySessionIsolationTests` 的请求与恢复期间切号测试 |
| 登录恢复将取消和网络失败归为退出状态 | 明确的 `credentialsRejected` 进入业务退出状态；取消、超时保持错误语义 | 恢复取消、超时与凭据拒绝测试 |
| 恢复任务依赖共享协调状态 | `CommunitySessionRefreshCoordinator` 由会话实例持有；同实例合并恢复，独立实例维护各自任务 | 并发恢复合并和独立协调器测试 |
| 恢复完成后可能保存迟到凭据 | 登录与恢复在持久化前核对身份及取消状态；同账号续期保持原登录代际 | App 登录适配与社区请求代际测试 |
| 日程同步成功与保存结果脱节 | 仓库的保存端口为 `async throws`；课表、短信续接与 DDL 同步等待写入完成 | 保存失败与 DDL 成功时机测试 |
| 连续编辑与缓存通知竞争 | 保存任务按仓库实例排队；通知延后重载，按本机修订保留继续编辑的内容 | 保存顺序、通知重载和保存期间编辑测试 |
| 旧账号保存任务与提示影响当前账号 | 任务捕获账号与仓库代际；重置取消排队任务，迟到失败按归属处理 | 旧账号失败和排队任务测试 |
| 日程磁盘实现绑定 App 全局目录、文件服务与云同步实现 | `SchedulePersistenceStore` 接收文件服务、根目录和用户状态比较器；actor 管理保护写入、迁移和版本校验 | 独立仓库、损坏保留和写入失败测试 |
| 日程领域层混入学校服务和平台操作协议 | 服务及平台端口归 `SchedulePorts`；模型、载荷、日期和规则归 `ScheduleDomain` | 编译依赖及导入校验 |
| 保存效果通过可变全局槽配置 | 云同步回调在 App 的保存适配中显式调用；外部展示通过生命周期适配器协调 | 生产调用链、生命周期实例测试 |
| 教学中心状态在基础模块隐式共享 | `TeachingCenterSessionState` 显式接收 Cookie 容器，学校服务显式接收会话状态；生产实例归 App 组装 | 学校认证容器隔离测试 |
| 生产成绩服务依赖登录单例、Bundle 和连接池 | 领域契约归 `ScoreDomain`，实现归 `ScoreInfrastructure`；App 构造器选择生产凭据、端点和传输 | 生产实现的注入请求与解析测试 |
| 页面构造依赖和环境依赖可能来自不同实例 | 页面入口持有构造依赖，内部视图安装同一实例；课程评价入口直接接收依赖 | App 宿主环境组合测试 |
| 文章与话廊切换使用字符串绑定 | 场景内使用枚举状态，跨场景切换使用回调与类型化内容绑定 | App 与 Feature 编译边界 |
| 系统日历导入获取完整日程缓存 | 平台端口接收课程快照和学期，平台适配器展开事件 | 平台动作替身与投影测试 |
| 共享快照库隐式选择生产容器 | 快照仓库和解析器显式接收实例；App、Widget、Watch 在入口选择文件服务和容器 | 共享仓库隔离测试、扩展编译及直接产品检查 |

## 职责与写权限

- `ScheduleRepository` 拥有当前账号的完整内存记录和保存顺序。课表、DDL、空教室使用所属字段的场景投影；云同步基线由持久化适配合并。
- `SchedulePersistenceStore` 拥有注入目录内的磁盘操作。读失败保留源文件并关闭写入，原子写入失败保留已存版本。
- `SchedulePorts` 定义业务与外部能力交互的协议。系统日历展开、权限、CloudKit、提醒、WatchConnectivity 和 WidgetKit 由 App 或扩展实现。
- `ScoreDomain` 定义成绩数据与学校认证服务契约。`ScoreFeature` 管理筛选、缓存和页面状态，`ScoreInfrastructure` 执行网络请求。
- 社区功能通过 `CommunitySession` 接入网络与恢复，通过 App 提供的目标工厂跨场景导航。身份代际属于会话生命周期，页面状态属于场景实例。
- 生产单例、连接池、系统容器和默认配置在组装入口选择；可复用状态机和服务通过注入参数消费能力。

## 验证与适用范围

包级验证入口为 `Scripts/run-extended-tests.sh modules`；App 行为入口为 `Scripts/run-extended-tests.sh catalyst`；通用 iOS 编译入口为 `Scripts/build-install-device.sh --compile-only --generic`；静态入口为 `Scripts/run-static-audit.sh`。产物覆盖 [构建与测试](TESTING.md) 规定的固定路径。

本轮行为回归覆盖模拟传输、文件故障、并发保存、身份变化、实例隔离和 SwiftUI 宿主组合。实际学校服务、设备权限、Watch 配对、后台刷新和 iCloud 双向同步继续由既有真机与 Smoke 流程提供验证。

| 最终验证 | 结果 |
| --- | --- |
| 静态审计 | 全部分组通过；源码质量扫描 254 个 Swift 文件 |
| macOS 原生包级测试 | 94 项通过，17 个测试组 |
| Mac Catalyst App 行为测试 | 214 项通过，跳过数 0 |
| 通用 iOS Release 编译 | 主 App、Widget、Watch App 与 Watch Widget 编译通过 |

Catalyst 最终日志包含 4 条 `SchedulePorts` 依赖扫描警告，涉及 `ScheduleDomain`、`ClientCore`、`StorageCore` 和传递依赖 `ScheduleContracts`。前三项已在 `Package.swift` 直接声明，传递关系通过 `ScheduleDomain` 声明；模块和原生 target 校验通过，链接及 214 项行为测试通过。包级测试与 iOS Release 编译通过。当前证据指向 Xcode 测试构建的依赖扫描诊断差异，具体根因继续保留为工具链排查项。Swift 社区存在显式声明依赖仍产生同类测试构建诊断的[原始复现记录](https://forums.swift.org/t/xcode-26-unable-to-find-module-dependency/80516/19)。

## 后续演进边界

1. `ScheduleCache` 继续作为版本化的聚合持久化记录，包含课表、DDL、空教室与日程偏好。跨场景协调通过字段投影控制写权限；进一步拆盘需同时设计事务与缓存迁移。
2. Gallery、Course、Paper、Mine 的接口实现与页面同属各自 Feature，依赖统一传输协议。独立网络发布或多客户端复用需求出现时，可沿现有 `Servicing` 协议提取实现。
3. App 壳层拥有全局路由、账号状态、平台连接池和系统能力适配。其生命周期及同步协调器保持可注入边界，生产实例对应进程和系统服务生命周期。
4. `MediaKit` 的图片解码与缓存包含进程级资源协调；设计系统包含系统交互组件。资源生命周期与业务账号数据分别维护。
5. 跨场景导航通过 App 目标工厂组合 `AnyView`，业务请求和实体标识保持类型化。后续路由扩展沿目标工厂增加明确参数和结果契约。

新增模块遵循实际的职责与生命周期边界。后续改动持续运行依赖规则和隔离回归，维护领域模型、服务实现、页面与平台适配之间的契约。
