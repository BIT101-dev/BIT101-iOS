# 系统架构与数据范围

BIT101-iOS 由 App 宿主、本地 SwiftPM 模块、Widget、Live Activity 与 Watch 组成。App 负责组装依赖和平台资源，各功能模块维护所属业务状态。模块定义见 [Package.swift](../Package.swift)，验证入口见 [构建与测试](TESTING.md)。

## 模块职责

| 模块或目录 | 职责 |
| --- | --- |
| `BIT101-iOS/` | 启动、登录、账号生命周期、设置、路由与平台适配 |
| `ScheduleDomain` | 课程、考试、个人日程、DDL、缓存格式、编辑和同步合并规则 |
| `SchedulePorts` | 学校服务、缓存及日程平台动作端口 |
| `ScheduleFeature` | 课表、DDL、空教室、编辑与认证续接的场景状态和页面 |
| `ScheduleInfrastructure` | 学校 CAS、教学中心、课程中心、乐学及响应映射 |
| `SchedulePersistence` | 账号日程文件的串行读写、迁移与版本比较 |
| `ScheduleSync` | 课表云同步状态机、冲突决策、推送与拉取协调 |
| `ScheduleContracts`、`ScheduleSharedStore` | 扩展共用快照、日程发生时间、持久化与版本范围 |
| `ScheduleActivityContracts` | ActivityKit 共用属性与状态 |
| `ScoreDomain`、`ScorePorts` | 成绩模型、比较、筛选及查询与缓存端口 |
| `ScoreInfrastructure`、`ScoreFeature` | 学校成绩请求、缓存、筛选、统计、可信成绩单与页面 |
| `CommunityCore` | 社区模型、分页状态、草稿与消息已读端口 |
| `CommunityTransport` | 社区请求、会话恢复、请求重放与账号归属 |
| `CommunityPersistence` | 发帖、文章与建议草稿、图片资产、消息已读快照 |
| `GalleryFeature`、`CourseFeature`、`PaperFeature`、`MineFeature` | 话廊、课程、文章、个人主页及各自服务和场景状态 |
| `CommunityUI` | 社区卡片、评论、链接与导航展示规范 |
| `MapFeature` | 校园地点、课程地点匹配、原生地图和定位呈现 |
| `ClientCore` | 学校认证、通用 challenge 和学校会话能力 |
| `TransportCore` | HTTP 传输、连接状态、请求预算、取消与错误解析 |
| `StorageCore` | 账号存储身份、文件服务、偏好仓库与文件执行器 |
| `DesignSystemKit`、`MediaKit` | 公共界面令牌和组件、媒体读取、缓存、解码、预览与容量协调 |

Domain 与共享 Contracts 定义业务模型和接口。资源通过端口、基础设施或 App 适配器访问。社区功能复用 Community 接口，地图依赖 ScheduleContracts 的地点规范化逻辑。静态审计核对允许依赖表与实际 import。

教学中心、普通成绩和可信成绩单共用 bit-login challenge 解码与验证码请求构造。`waiting_captcha` 携带内联图片，通过 `/api/auth/{id}/captcha` 提交区分大小写的验证码；`waiting_sms` 通过同一面板提交短信码。阶段变化清空输入并继续当前业务；明确失败结束当前挑战，原始拒绝原因传给统一错误呈现。短期令牌与验证码图片由当前账号会话的内存持有。

## App 组装与状态流

App 在壳层组装账号存储、网络客户端、学校服务、媒体环境、平台动作和页面依赖。功能入口使用同一组装环境；页面持有所属 ViewModel，跨页面跳转通过壳层路由和功能端口传递业务身份。

壳层按窗口特征管理方向：普通 iPhone 与 Duo 外屏采用竖屏，Duo 内屏支持横竖屏，iPad 跟随系统窗口方向。方向策略随窗口特征变化重新提交给 UIKit。DesignSystemKit 提供共享窗口布局环境和分栏、网格、阅读宽度规则，功能页面持有同一份筛选、选中项和编辑状态。话题和文章的浏览容器拥有导航分栏及列内导航栈，壳层直接使用该容器。组合页面传递可见状态，课程列表的请求与恢复监听跟随活动分栏。

`AppStorageSession` 为账号生成偏好键和安全目录名，访客使用固定分区。任务创建时捕获账号、登录代际和页面请求代际；异步结果在提交页面或持久化前核对所属身份。账号切换由生命周期协调器重载缓存、偏好、同步状态和扩展展示。登录、注册与密码重置的页面任务持有提交操作，离开页面结束所属任务，服务保存会话前核对取消与账号归属。

注册、密码重置与社区写入共享传输结果判定，区分发送前失败、服务端明确拒绝和结果待确认。注册或重置的响应丢失后，使用本次新密码确认社区登录；结果继续待确认或本机会话保存受阻时，保留输入并提示通过登录核对，验证凭据随本次提交结束。

请求、保存、上传和清理由对应场景持有。页面或账号生命周期结束后取消所属工作，迟到结果继续接受归属核对。更新检查、提醒、同步和网络警告按各自生命周期协调：App Store 常规版本检查与 Cloudflare 紧急更新通知双通道独立校验 HTTPS 端点并协同提示，用户操作触发的学校请求由所属动作继续执行。

学校密码输入、学校短信、教学中心认证与预热、社区认证恢复共用按账号代际合并任务的协调器。学校短信由当前可见分区承载，校验完成后继续所属查询；同账号更正密码后更新 Cookie 容器，退出或切换账号会取消恢复任务。CAS 恢复与 service 登录共用表单、风控载荷和请求构造，指纹异常时提交协议定义的 `error: true` 载荷并继续密码与短信校验。乐学读取保留教学中心已验证路线与预热状态，诊断探测在短信挑战处返回待验证状态；单个等待者取消仅结束自身请求，全部离场或账号变化后取消认证操作。

SwiftPM 使用 Swift 6.2 与 MainActor 默认隔离。页面状态由 MainActor 发布；跨隔离域值声明 Sendable，纯业务类型按职责采用 nonisolated。JSON 解码、成绩解析和较大响应转换使用 `@concurrent`，继承调用任务的优先级、取消与任务局部值。同步磁盘工作通过 `StorageFileExecutor` 的独立串行队列执行，文件仓库在所属 actor 中维护顺序。

## 日程与成绩

### 课表、DDL 与空教室

`ScheduleRepository` 为课表、DDL 和空教室提供账号内共享数据，课表投影按数据修订号复用。仓库串行保存并将排队中的同源修改合并为最新快照；外部同步通过基线执行三方合并，并发冲突进入版本选择。学校课程与首周日期构成课表更新，考试接口独立返回（临时故障保留同学期考试，成功空列表清空该学期考试），按学期存入 `schedulesByTerm` 并滚动保留相邻学期供成绩匹配。调课编辑复用缓存楼宇目录并支持自定地点；分享码保存已排课程与来源时间表，小组件定位主课表当前周，系统日历事件优先使用本地目标学期快照。

课程中心与乐学独立推进 DDL 同步，成功后立即保存展示，内容未变时复用课表提示，部分来源失败时展示警告。课程中心按课程替换成功快照并保留失败或待确认缓存，全部成功后判定来源删除。学校事件完成状态与撤销按稳定 ID 同步，点击后交由系统浏览器定位对应作业或日历，手动 DDL 保留本机详情与编辑。磁盘与云端共用字段约束与逐条恢复，日程页与设置页共用读取重试和恢复确认，受阻或遇到新格式版本时保留原文件。

空教室按学校时区的自然日控制自动刷新：每日首次进入更新校区、当前教学楼目录与占用，同日复入和重启复用账号内缓存；手动刷新同时更新当前目录和占用。刷新与选择查询共享任务所有权，选择变化取消旧查询，教学楼和查询日期在认证前捕获，学期从学校当前响应确定。缓存按学期、教学楼和查询日区分，节次与当前分钟筛选在本地计算。当天查询成功后低优先级预取当前教学楼次日占用；自动查询失败保留当天有效结果与更新时间，跨日占用显示过期提示，本地日程存储受阻时空教室继续在所属账号内存中运行。校园地图按页面可见性和场景活跃状态管理定位，页面退出时释放待完成的定位请求。

### 成绩与可信成绩单

成绩查询将在线获取与本机持久化分开处理，成绩的筛选、排序与统计快照随源记录和筛选条件更新。缓存读取受阻时继续请求学校服务，在线结果留在页面内存，保存问题单独呈现。一次成绩刷新共享总表快照和最终认证通道，HTML 解析在后台执行，学校等级成绩保留原值并按领域映射统计 GPA；课程详情以四个并发请求共用详细查询预算，完成后按总表顺序返回。简略结果按课程匹配并保留已确认的详细字段，取消或局部失败保留可用结果及对应缓存，协议校验失败回写原始请求。学期与种类共用多选交互和账号内筛选偏好，种类选项从非空课程性质动态生成，学校课表补充未出分课程和学期上下文；成绩缓存区分简略与详细更新时间，读改写保留扩展字段，并提供与在线刷新互斥的账号内确认恢复。

可信成绩单将验证码认证与下载分开，重试复用已认证挑战。各页完成校验与后台解码后立即展示，补页独立推进，来源失效时保留已取得的有效页；当前报告与替换报告共享总解码预算与存活位图预算，替换页面完成后统一交接展示。重试向同一报告补齐缺页，重新申请取得新报告来源并根据新来源继续补页；验证码续接由页面模型持有，页面退出时取消下载，报告级认证或来源失效及时结束余页下载。

## 社区、消息与草稿

### 列表、详情与评论

跨页面评论呈现和正文链接归 `CommunityUI`，分页与草稿规范归 `CommunityCore`，详情、评论和编辑由所属功能服务处理。各场景独立维护首屏、分页、搜索和刷新代际，刷新期间保留既有内容与游标；主 Tab 保留页面排序和滚动位置，进出页面时暂停或恢复请求。社区读取共用网络恢复、前台激活和重入重试规范，帖子空态与内容共用可下拉刷新的滚动容器。可选鉴权读取遇会话过期先尝试公开内容并后台合并恢复凭据，点赞等待认证后读取结果。

社区详情与卡片通过共享计数流同步点赞、评论和课程评分，列表按字段修订原位合并卡片，刷新失败或取消时保留新计数。帖子列表与详情共享资源身份、展示字段与图片恢复规则，列表正文按字节预算截断，用户或标签缺失附加字段时继续展示可用内容。课程搜索在加载与失败期间保留输入区；文章预取按账号、代际和登录状态共享四个名额，打开详情先展示预取内容再核对正文。长帖与长评论支持原生全文阅读，文章富文本逐块准备并响应取消，话廊网页后续加载失败时保留当前文档与滚动位置。

详情评论保留首屏刷新与分页的失败标记，连接恢复、重新进入或回到前台后重试对应请求，已有评论和已确认交互持续可读；评论发送结果待确认时保留完整提交范围，用户核对列表并确认后可再次发送。

### 草稿、媒体上传与消息已读

发帖、文章和建议复用账号草稿存储与串行写入事务，文章草稿汇集于 `composer-paper.json`，损坏条目保留在原归档中，有效草稿继续使用；用户确认恢复存储后保留有效条目并清理损坏内容，当前页面输入继续保留。发帖与评论共用图片草稿、上传状态、重试和移除，元数据与资产分开保存（单张预算 1 MiB，最多九张），文字暂存复用相同字节的资产版本，恢复草稿继续复用已有上传结果。各编辑面板均按当前输入状态保护下滑关闭。

创建、状态切换与更新由业务调用方声明结果含义。帖子和文章在创建请求前将所属账号与提交内容原子写入 `composer-publications.json`，结果待确认时要求核对本人已发布内容或进入带入标题的原生搜索；取得成功回执后清理已提交草稿及发布记录。文章、帖子与个人资料更新的响应丢失后重读远端内容，字段相符时确认成功，版本冲突或待确认时保留编辑输入并提供核对入口；建议响应丢失时保留完整载荷并复用提交身份。

消息中心先提供历史首屏，历史分页（使用实际末条 ID）与未读窗口保存、服务端分类清零确认分别推进；摘要端点或本地已读文件受阻时，消息正文继续可读，角标与确认状态保留恢复信息。已读快照位于账号目录的 `message-read-snapshot.json`，通过受保护的原子写入提交，按分类保留 1024 项已读历史，外部写入和账号切换使查询缓存失效。

## 网络会话与隔离

`HTTPTransport` 与 `HTTPClient` 提供统一传输、观察和错误映射。URLSession 由所属传输实例持有，连接池在 App 选择 Cookie、缓存、重定向、连接等待及期限策略。最后一个客户端释放传输后结束在途请求并关闭会话，Cookie 容器切换随传输资源一起处理。

| 会话 | 范围 |
| --- | --- |
| 社区 | 共享所属账号的 Cookie、缓存与连接池 |
| 普通成绩与可信成绩单认证 | 共用认证传输，各自持有业务 challenge |
| 敏感下载 | ephemeral 配置，正文由当前页面持有 |
| 学校 CAS | 按业务选择手动重定向与 HTTPS 升级策略 |
| 教学中心及课程中心 | 独立会话、可失效认证状态和短信续接 |

社区认证失败由统一恢复策略协调续期与重放。凭据遭拒时暂停社区鉴权请求，保留本机账号、学校凭据与缓存阅读；账号登录使用 BIT101 密码，主动退出负责清理会话。连接问题保留当前会话。请求发送、恢复、解码与副作用提交继续核对登录代际。学校会话恢复、短信及有副作用的请求分别按所属协议处理重试。

社区删除接受目标端点返回的成功状态或 404，并继续校验最终请求方法与账号代际，支持响应丢失后的幂等重试。

连接池限制整体资源期限并保留更短的业务期限；持续响应受同一预算约束。响应聚合追加同一 URLSession 任务的数据块并检查取消，JSON 和媒体各有字节上限。错误正文按解析与展示预算处理，结构化错误和简短纯文本用于提示，HTML 与未知结构按 HTTP 状态呈现。协议声明的资源缺失映射为所属服务类型，通用路由错误保留 HTTP 状态与原始说明。

`NetworkPathState` 提供实例级连接快照和连接恢复事件，页面处理所属业务重试，共享媒体环境处理图片恢复。网络提示通过既有队列异步呈现并保留冷却窗口，请求持续执行。诊断在固定容量中兼顾近期请求、故障与相邻上下文，并按账号代际隔离；业务状态与响应解析失败回写对应请求记录，响应解码保留字段路径和底层原因。传输中断和响应超限保留已收到的状态、响应头、容量受限的正文及最终请求，原始错误继续传播。学校服务恢复使用学校协议登记的网页入口；原始与最终请求地址继续用于诊断和报告脱敏。

社区登录优先调用 `/user/login`，账号缺失与密码错误的合并响应进入学校身份补充验证，并通过 `login_mode: true` 保留已有社区密码。社区密码摘要与学校密码分开存入 Keychain；社区密码验证成功后更新摘要，已有学校密码继续复用；学校凭据缺失时将本次登录密码作为首次认证候选，CAS 明确拒绝后共享一次学校密码输入。旧会话恢复先尝试已有凭据的社区登录，凭据存在差异时补充学校身份验证。

首次建立本机账号遇到社区服务故障时，在独立 Cookie 容器中复用学校密码或本次输入完成 CAS 与短信验证，密码遭明确拒绝后再弹窗收集替换密码。无 action 的登录表单提交到当前文档地址并保留 service 参数，取得指定 service 票据后确认身份并写入 Keychain。学校功能、Widget、Watch、提醒、实时活动和装机就绪依据本机有效会话判断；学校独立登录会话在访问社区时按账号代际合并恢复，公开读取先返回结果再后台恢复。切换账号或取消立即结束验证，核对身份后才保存账号并交接学校 Cookie。

学校密码与原生短信输入共用提示退场等待，取消时清理敏感输入并结束所属等待。

学校服务优先复用本机 CAS 票据，教学中心、教务成绩与可信成绩单分别建立业务会话，校外路线在本机登记 WebVPN 指纹、提交风控令牌并完成回调。业务 Cookie 按域和路径传递，认证与下载持续核对登录代际；成绩 HTML 直接映射表头，简略与详细查询共享本机认证，本机传输或协议故障进入有界 bit-login 回退。乐学优先直连学校，WebVPN 在本机完成认证。

学校协议适配层为认证限制、账号锁定、会话失效和资源访问限制保留类型化错误，CAS 页面与中转错误共用锁定识别。账号锁定立即结束当前认证并提供统一认证入口，服务故障提供学校服务检查入口，提示模型与页面失败态共用错误链与操作文案。已发布客户端的响应标记由报告端核对并在配额写入前过滤学校侧异常；解析、缓存及协议适配问题保留开发者诊断，学校请求失败时保留已有课表和本地编辑能力。

外部 BIT101 后端、Android 和 Web 项目属于只读参考及对应维护者的工作范围。iOS 保存请求与响应证据，负责协议适配、错误呈现和恢复。Cloudflare 自有 Worker、隐私页面和分享链接由本仓库维护，部署与发布按授权执行。

## 存储与账号隔离

| 数据 | 位置与生命周期 |
| --- | --- |
| 学校凭据与社区会话凭据 | Keychain，按账号选择与安装状态维护 |
| Cookie、challenge、access token、短信状态 | 所属会话内存与 Cookie 容器，按账号及失效事件更新 |
| 主题、旋转、自动更新检查等设备偏好 | 应用级 UserDefaults |
| 账号设置、成绩筛选与消息已读 | 账号级偏好或所属业务仓库 |
| 日程、成绩与草稿 | 账号隔离的 Application Support 文件 |
| 可重建图片与头像 | 系统 Caches，按容量和近期访问回收 |
| Widget 与 Watch 展示 | App Group 中的精简快照及版本范围 |

`AppFileService` 统一文件内容、目录、元数据、保护和规范路径操作。生产读取先验收容量，再读取有界字节；写入准备所属目录并使用受保护的原子提交。用户持久目录参与系统备份，历史备份元数据在场景启动后完成一次迁移，日常写入维护所属目录的策略；可重建缓存和临时展示按各自生命周期清理。

`AccountScopedCodableStore` 统一偏好键、迁移、编码和扩展字段保留。读取区分缺值、有效值与损坏值；未知格式保留原数据并暂停对应保存与云同步。账号设置与成绩筛选提供独立恢复入口，确认后恢复当前账号快照并重建所属同步域的派生合并基线，日程、成绩、登录及设备偏好分别管理生命周期。

本地数据清理通过 App 组装的资源所有者执行，覆盖偏好、凭据、文件、Cookie、URLCache、媒体和共享快照。清理前等待已接收的存储操作结束，异常按资源保留诊断。社区线上写入的待恢复事务先完成对应恢复，再按账号范围处理本机清理。

## iCloud 同步

课表通过 CloudKit 同步用户状态，App 负责容器、记录和 system fields 适配；学校原始数据由客户端直接获取。同步状态机维护拉取、合并、冲突选择和推送的互斥关系，并在启动、前台恢复和账号切换后按所属生命周期运行。

手动 DDL 的图片压缩后随本机记录保存，每条最多九张、单张 1 MiB、全部附件共 16 MiB。CloudKit 将普通 JSON 元数据与 `ddlImagesAsset` 资产分开存储，拉取时按 DDL 稳定 ID 还原图片；普通字段沿用 1 MB 预算，含附件的本机缓存上限为 64 MiB。资产写入串行复用固定暂存路径，并在提交后释放。

本机持久化保存已确认的用户状态作为三方合并基线。独立记录按稳定 ID 合并，相对基线的删除继续传播，顺序和同一字段的并发分歧进入冲突决策。提示按是否存在共同基线说明合并范围：已有基线时选择冲突项的优先来源，首次关联时选择整体用户状态的来源。比较写入核对磁盘版本和云端基线，保存期间的新编辑继续保留待同步状态。

成绩 KVS 同步使用加密载荷，密钥由 iCloud 钥匙串协作。实验性偏好同步分别管理设置、筛选和已读业务域；字段修改、可选值清除和已读并集按所属版本合并。账号事件、保存通知和同步实例显式注入，业务存储成功后推进对应云版本。

## 媒体与设计系统

通用颜色、字体、间距、页面状态、刷新行、编辑器、标签、评论和原生交互组件归 DesignSystemKit。社区共享展示归 CommunityUI，功能页面使用公共组件并持有实际业务动作。详细界面约定见 [设计系统](DESIGN_SYSTEM.md)。

媒体环境注入传输、图片文件服务、预览文件服务和容量协调器。`CommunityImage` 统一验收 HTTP(S) 图片地址，媒体入口将 HTTP 升级为 HTTPS，缓存与在途请求按升级后的安全地址合并。头像、列表静态图和详情优先读取已有原图及低清缓存；下载按低清与原图地址恢复，低清故障时继续尝试原图。列表和详情静态图共用加载器，详情在低清展示后继续准备原图。共享媒体环境在联网和回到前台时恢复失败图片；启用系统“减弱动态效果”时，渐进换图直接更新。

话廊与头像按 URL 共享原始图片字节、下载任务、磁盘文件和资源租约，位图解码在展示预算内复用。静态位图、头像与 GIF 共用展示预算管理，文件读取与解码使用独立执行器，内存压力释放可回收预算，等待中的视图在预算可用时继续加载。磁盘图片首次或到期扫描建立容量与访问时间库存，写入按条目更新容量并执行回收，显式策略变更和清理更新库存；回收跳过活跃展示文件，按近期访问顺序释放可重建内容。图片缓存写入故障时，有效字节进入受容量约束的内存缓存并继续显示，旧文件通过后台存储执行器清理。

照片读取在系统提供者的有效期内按预算完成，压缩和静态、动画解码在后台执行；图片、头像和预览共用原始字节及位图预算。DDL 与社区草稿共用逐张导入流程，单张失败后继续处理其余图片，任务取消与所有者变化时结束导入。草稿缩略图按预览数据与显示比例在后台准备，编辑界面重绘复用已准备的位图。动图原文件就绪前保留静态预览，原图加载失败后继续展示可用图片。

Quick Look 独立以模态展示，由系统管理分页与工具栏；使用明确准备的本地 URL，优先展示缓存，缓存缺失时立即提供原生加载与关闭控件。低清和原图在预览内并行准备，可用资源就绪后原位展示，来源视图结束时关闭预览并释放资源。活跃预览文件由所有权登记保护，文件创建、登记、回收和清理共享同一资源管理范围；本地图片和成绩单的系统预览文件写入受保护的临时目录，预览结束释放并清理已登记的配额条目，启动时回收残留，目录扫描按既有周期与显式清理执行。

## Widget、Watch 与 Live Activity

App 将当前账号日程转换为精简共享快照，包含课程、个人日程与 DDL 的扩展展示字段。DDL 摘要提供空标题显示值，按共享字段的 UTF-8 预算截取文字，身份或日期异常的记录独立过滤。共享身份、修订与时间线规则归 ScheduleContracts，磁盘协调归 ScheduleSharedStore。Widget、Watch App 和 Watch Widget 共用相同的业务接口。

个人日程按重复日期展开，与课程按开始时间合并；个人日程独立于学期首日。DDL 时间线复用一次排序，围绕当前可见条目生成刷新节点，窗口推进后继续请求下一批。

共享快照读写在后台执行，账号切换和退出清空所属展示。凭据读取待恢复时保留已发布课表、提醒与活动，读取恢复后按账号代际继续同步；装机就绪随登录呈现和凭据恢复重新核对。Watch 前台重读受限时保留已确认快照，在后台按当前时间重算课程并显示缓存提示；快照变更、退出与成功清理执行所属内容失效。Watch 清理保存精简版本标记，重启后继续拒绝迟到旧传输，新版本到达后恢复。请求、回复和持久化共同核对最高已接受修订，断线后支持前台再次请求。

日历导入、提醒和 Live Activity 由 App 平台适配器读取课程及账号上下文。日历事务串行维护展开、写入与回滚，通知替换保留失败恢复状态；权限返回后再次核对账号。ActivityKit 属性独立于纯领域模型，系统界面与投递通过真机专项验收。

系统日历事件保存所属账号、学期及日程标记，链接回到对应课表详情。地点对象以完整教室文本作为标题，已匹配的校园建筑提供校准坐标；其余地点保留文本。完整地点文本供系统日历及锁屏组件读取。导入索引受损时，课表设置提供确认后的重建入口，从系统日历中近十年与未来十年的当前账号标记恢复批次，保留事件内容。批次按学期和日历归属维护，增量导入保留各日历中的其余事件；删除时根据已记录日历的标记重新定位同步后改变标识的事件。

## 服务质量门禁

静态审计复用当前工具链的 SwiftSyntax 事实，核对依赖方向、资源归属、公开能力、自动学校请求、设计系统和测试登记。基础传输、媒体与平台资源按明确签名归属，新增业务能力进入对应网络和交互库存。

原生构建验收 Swift 类型、隔离与平台编译行为，行为测试验收状态、取消、失败恢复和持久化，UI 与人工专项验收真实控件及系统能力。检查器作者提供触发、合规和故障样例，较大源码按生命周期和职责审查，维护文件统一遵守 1000 行上限。

验证输入使用提交、环境和实际内容身份关联结果。编译缓存、工具链选择、测试库存、原始结果及发布证据由既有脚本维护；开发时选择受影响分组，检查器自测由统一审计集中执行。工作流命令、固定产物和 CI 范围统一见 [构建与测试](TESTING.md)。

## 开发与验证基础设施

### 输入与结果复用

编译验收覆盖完整产品输入。网络与 iCloud 采样绑定生产能力、模块依赖、壳层资源、manifest 与脚本输入，独立模块改动按依赖决定专项复验。完整行为组与 UI 组通过事务合并到固定结果路径并保留各自执行身份与性能采样；定向复验更新 `diagnostics/test-results.xcresult`，完整验收使用 `test-results.xcresult`。报告、活动记录与截图按写入时间选择当前包，元素树与崩溃日志汇集为带来源说明的诊断文本；覆盖率按平台可执行源码验收。

本地验证直接比较所属文件内容、执行权限和环境，相同内容在提交前后沿用身份。共享证据以稳定的匿名身份交换本机路径与设备标识。已提交输入按 Git 第一父提交链读取相关差异，合并提交纳入相对第一父提交的改动；所属组与 Worker 共用这一标识规则，其他文件的改动复用已有结果。公开发布回执核对已提交输入和工具链。大型文件等维护候选保存在固定代码质量报告中，按需打开审阅。

### 原始结果与批次

同类日志、截图和报告覆盖固定路径。`test-metrics.txt` 保存构建与运行耗时、逐例结果、最慢用例、进程及交互统计。`report json` 和 `report coverage` 读取当前批次的模块事件及模块覆盖率，或原生结果包。报告按指标和结果包的完成顺序选择当前来源；新构建结果优先于旧测试指标，构建诊断从对应结果包读取。

模块测试失败时同样生成当前批次指标，`report` 与 `report json` 呈现本次失败和模块日志；事件采集失败会说明原因。模块测试成功后生成覆盖率。

原生结果保存到固定结果包，中断时恢复前序结果。相邻完整测试组共同汇总，同组再次完整执行时开启新批次；`verify` 从首组开始组织完整验收批次。定向复验保留相同输入和环境下的完整结果，发布验收核对采样时效。输入和工作负载相同时复用性能采样。

输入变化、相关失败或证据过期时，所属完整组进入重新验收。模块测试及诊断整理保留当前原始失败包，新的结果生产流程覆盖所属诊断。CI 汇总完成后清理远端缓存，并上传构建失败的原始诊断包。

### 公共缓存与工作流资源

缓存维护保留增量编译所需文件，共享 SDK、模块、原生 CompilationCache 和索引，保留当前产物与测试宿主的配套符号；孤立符号按产物生命周期回收。编译结束后按 CAS 分配空间或构建数据库的累计增长触发维护，空闲页达到阈值且磁盘具备整理空间时使用 SQLite VACUUM 回收空页。

原生维护在独立子进程中执行，每个原生存储按容量目标管理当前代与上游代。固定报告 `.build/compiler-cache/compilation-cache.json` 保存项目、CAS、SDK、模块、索引、构建及诊断占用。远端缓存按来源提交与工具链选择，验证资料读取受阻时保留待核验缓存；恢复失败后根据当前源码编译，缓存与诊断保持原始形式，CI 产物使用零压缩传输。

构建与静态条件求值共享编译缓存的读锁；目录初始化、迁移和回收持有写锁。工作流先取得工作副本产物锁，再取得用户级共享资源锁。切换本机验收设备时，按项目记录的设备标识关闭上一台运行中的设备，保留设备数据。超时、取消与退出时回收整个工作流进程组的后台工作。

App 与扩展使用 Release 编译配置验收，XCTest 和 UI 测试包采用增量编译，定向修复复用其他测试文件的编译产物。UI 交互在本地真机验收。

### 静态事实缓存

SwiftSyntax 事实保存在固定 SQLite 数据库中，跨审计复用。原始源码与各编译条件库存使用独立上下文，正文相同的文件共用原始事实。索引器源码、工具链和交互规则共同决定缓存版本；版本变化后重建事实并回收旧存储页，源码按实际内容更新，已删除文件的条目同步回收。

### CI 结果归集

各验证组通过完整验收后生成独立结果记录，复用时核对来源提交、运行、输入差异、实际 Xcode、编译器、SDK 和宿主系统。发布流程核对行为测试的全部用例、参数实例、来源提交、实际设备、合并覆盖率及本地真机生成的 UI 验收证据。
