# 架构与数据边界

BIT101-iOS 由 App 宿主、本地 SwiftPM 模块、Widget、Live Activity 与 Watch 组成。App 负责组装依赖和平台资源，各功能模块维护所属业务状态。模块定义以 [Package.swift](../Package.swift)为准，验证入口见 [构建与测试](TESTING.md)。

## 模块职责

| 模块或目录 | 职责 |
| --- | --- |
| `BIT101-iOS/` | 启动、登录、账号生命周期、设置、路由与平台适配 |
| `ScheduleDomain` | 课程、考试、个人日程、DDL、缓存格式、编辑和同步合并规则 |
| `SchedulePorts` | 学校服务、缓存及日程平台动作端口 |
| `ScheduleFeature` | 课表、DDL、空教室、编辑与认证续接的场景状态和页面 |
| `ScheduleInfrastructure` | 学校 CAS、教学中心、课程中心、乐学及响应映射 |
| `SchedulePersistence` | 账号日程文件的串行读写、迁移与版本比较 |
| `ScheduleSync` | 课表云同步状态机、冲突决策、推送与拉取协调 |
| `ScheduleContracts`、`ScheduleSharedStore` | 扩展共用快照、日程发生时间、持久化与版本边界 |
| `ScheduleActivityContracts` | ActivityKit 共用属性与状态 |
| `ScoreDomain`、`ScorePorts` | 成绩模型、比较、筛选及查询与缓存端口 |
| `ScoreInfrastructure`、`ScoreFeature` | 学校成绩请求、缓存、筛选、统计、可信成绩单与页面 |
| `CommunityCore` | 社区模型、分页状态、草稿与消息已读端口 |
| `CommunityTransport` | 社区请求、会话恢复、请求重放与账号归属 |
| `CommunityPersistence` | 发帖、文章与建议草稿、图片资产、消息已读快照 |
| `GalleryFeature`、`CourseFeature`、`PaperFeature`、`MineFeature` | 话廊、课程、文章、个人主页及各自服务和场景状态 |
| `CommunityUI` | 社区卡片、评论、链接与导航展示合同 |
| `MapFeature` | 校园地点、课程地点匹配、原生地图和定位呈现 |
| `ClientCore` | 学校认证、通用 challenge 和学校会话能力 |
| `TransportCore` | HTTP 传输、连接状态、请求预算、取消与错误解析 |
| `StorageCore` | 账号存储身份、文件服务、偏好仓库与文件执行器 |
| `DesignSystemKit`、`MediaKit` | 公共界面令牌和组件、媒体读取、缓存、解码、预览与容量协调 |

Domain 与共享 Contracts 维护纯业务合同；资源访问经端口、基础设施或 App 适配器承接。社区功能复用 Community 合同，地图沿明确依赖的 ScheduleContracts 复用地点规范化。跨功能依赖由允许依赖表和实际 import 共同验收。

教学中心、普通成绩和可信成绩单共用 bit-login challenge 解码与验证码请求构造。`waiting_captcha` 携带内联图片，通过 `/api/auth/{id}/captcha` 提交区分大小写的验证码；`waiting_sms` 通过同一面板提交短信码。阶段变化清空输入并沿所属业务继续；明确失败结束当前挑战，原始拒绝原因传给统一错误呈现。短期令牌与验证码图片由当前账号会话的内存持有。

## App 组装与状态流

App 在壳层组装账号存储、网络客户端、学校服务、媒体环境、平台动作和页面依赖。功能入口消费同一组装环境；页面持有所属 ViewModel，跨页面跳转通过壳层路由和功能端口传递业务身份。

壳层按窗口特征管理方向：普通 iPhone 与 Duo 外屏采用竖屏，Duo 内屏支持横竖屏，iPad 沿系统窗口方向运行。方向策略随窗口特征变化重新提交给 UIKit。DesignSystemKit 提供共享窗口布局环境和分栏、网格、阅读宽度规则，功能页面持有同一份筛选、选中项和编辑状态。话题和文章的浏览容器拥有导航分栏及列内导航栈，壳层直接承接该容器。组合页面传递可见状态，课程列表的请求与恢复监听跟随活动分栏。

`AppStorageSession` 为账号生成偏好键和安全目录名，访客使用固定分区。任务创建时捕获账号、登录代际和页面请求代际；异步结果在提交页面或持久化前核对所属身份。账号切换由生命周期协调器重载缓存、偏好、同步状态和扩展展示。登录、注册与密码重置的页面任务持有提交操作，离开页面结束所属任务，服务保存会话前核对取消与账号归属。

注册、密码重置与社区写入共享传输结果判定，区分发送前失败、服务端明确拒绝和结果待确认。注册或重置的响应丢失后，使用本次新密码确认社区登录；结果继续待确认或本机会话保存受阻时，保留输入并提示通过登录核对，验证凭据随本次提交结束。

请求、保存、上传和清理由对应场景持有。页面或账号生命周期结束后取消所属工作，迟到结果继续接受归属核对。更新、提醒、同步和网络警告按各自生命周期协调，用户操作触发的学校请求由所属动作继续执行。

学校密码输入、学校短信、教学中心认证与预热、社区认证恢复共用按账号代际合并任务的协调器。学校短信由当前可见分区承载，校验完成后续接所属查询。同账号更正学校密码后更新 Cookie 容器，当前认证等待者继续完成所属查询；账号退出与切换取消该身份的恢复任务。CAS 恢复与 service 登录共用页面表单、风控载荷和请求构造，首次返回的短信页面沿同一验证流程续接。指纹服务返回有效令牌时提交令牌和组标识；服务异常时提交协议定义的 `error: true` 风控载荷，由学校继续执行密码及后续验证，任务取消沿原取消路径结束。乐学读取保留教学中心已验证的路线与预热状态，诊断探测沿已有 Cookie 读取并在短信挑战处返回待验证状态。等待者取消时立即结束自己的请求，其余等待者继续共享输入；全部等待者离场或账号变化后取消所属认证操作。

SwiftPM 使用 Swift 6.2 与 MainActor 默认隔离。页面状态由 MainActor 发布；跨隔离域值声明 Sendable，纯业务类型按职责采用 nonisolated。JSON 解码、成绩解析和较大响应转换使用 `@concurrent`，继承调用任务的优先级、取消与任务局部值。同步磁盘工作通过 `StorageFileExecutor` 的独立串行队列执行，文件仓库在所属 actor 中维护顺序。

## 日程与成绩

课表投影按仓库数据修订号复用；成绩的筛选、排序与统计快照随源记录和筛选条件更新。

`ScheduleRepository` 为课表、DDL 和空教室提供账号内共享数据，各子功能拥有请求与提示状态。仓库串行提交保存，等待写入的同源本机修改合并为最新快照，显式等待沿合并后的提交完成；排队期间继续保留页面编辑；外部同步更新通过基线进行三方合并。相同记录的并发分歧进入明确的版本选择，选择作用于冲突记录，双方独立编辑共同保留；合并完成后继续保存并同步。

空教室按学校时区的自然日控制自动刷新：每日首次进入更新校区、当前教学楼目录与占用，同日复入和重启复用账号内缓存。教学楼目录按校区记录每日刷新，手动刷新同时更新当前目录和占用。占用查询独立取得学校当前学期，缓存按学期、教学楼和查询日区分，节次与当前分钟筛选在本地计算；切换教学楼首次查询后同日复用。自动查询失败后保留当天有效结果与成功更新时间，手动刷新支持立即重试；跨日占用沿过期提示引导刷新。本地日程存储受阻时，空教室选择与在线查询继续在所属账号内存中运行。

调课编辑使用全校区已缓存的楼宇目录，保留原地点并支持自定地点。分享码投影已排课程，待排条目保留在本地。自己的课表小组件定位主课表当前周；系统日历事件优先使用本地目标学期快照，支持离线定位。

学校课程与首周日期形成课表更新，考试接口独立返回状态；考试暂时故障时保留同学期已有考试，成功返回的空列表清空该学期考试。学校课程、考试和首周日期按学期存入 `schedulesByTerm`，展示由当前学期、手动首周日期和调课规则派生。完整日程按相邻学期滚动保留，归档课程供成绩匹配。个人日程、分享课表、手动课程规则和手动 DDL 使用稳定身份；分享导入保存独立记录和来源时间表。

磁盘与云端准入共用身份、日期、节次、课程和事件约束。支持格式的有效内容按字段和记录恢复，加载结果携带恢复状态；日程页与设置页共用读取重试和恢复确认，页面继续展示有效内容，原文件保留至用户确认。确认后提交完整快照并恢复编辑与云同步。同步选择独立恢复，未知选择保持关闭。

日程根文件损坏时，用户可确认以当前有效内存重建所属账号的缓存，确认动作核对账号代际。写入前再次核对磁盘，期间出现的可读版本继续保留。文件访问受阻、超出预算或较新格式版本沿原文件保护与重读流程处理。

课程中心与乐学独立推进 DDL 同步，各来源成功后立即保存并展示。课程中心记录作业所属课程，成功课程替换其快照，失败课程与归属待确认的缓存继续保留；完整成功后完成来源删除判定。课程目录或共享活动身份发生分歧时保留该来源快照。学校事件完成状态及显式撤销按稳定 ID 保存并同步，手动事件独立维护。学校 DDL 点击后交给系统浏览器，课程中心按课程与活动标识定位作业，乐学定位截止日期的日历；历史课程中心记录缺少课程标识时打开课程中心首页。手动 DDL 保留本机详情与编辑。课程中心分页、并发、响应期限与 ICS 支持范围由服务实现及对应契约测试维护。

成绩查询将在线获取与本机持久化分开处理。缓存读取受阻时继续请求学校服务，在线结果留在页面内存，保存问题单独呈现。简略结果沿匹配课程保留已确认的详细字段，取消详细查询后恢复原有完整快照；详细请求失败时保留可用结果及对应缓存。页面复入与外部缓存变更同样保留当前可用内容。成绩详情保存课程身份并解析当前结果，刷新、详细字段补齐与未出分状态变化沿同一选中项更新。

一次成绩刷新共享总表快照和最终认证通道。HTML 解析在后台执行，学校等级成绩保留原值并沿领域映射统计 GPA；课程详情以四个并发请求共用详细查询预算，完成后沿总表顺序交付。局部失败保留已取得的详情与匹配缓存，页面继续展示可用成绩。协议校验失败回写原始请求。

学期与种类共用多选交互和账号内筛选偏好。种类选项从本机成绩缓存中的非空课程性质动态生成，在线成绩到达后同步更新；学校课表补充未出分课程和学期上下文。全选分类时保留分类缺失的可用课程，具体分类按对应字段筛选。

成绩缓存区分简略与详细更新时间，读改写保留支持格式中的扩展字段。简略阶段保留匹配课程的已知详情，全选筛选随返回字段目录更新。成绩缓存与筛选存储提供账号内的确认恢复，重建时保留当前可用成绩。恢复与在线刷新互斥，恢复结果核对账号和展示代际，页面使用所属操作的有效数据。

可信成绩单将验证码认证与下载分开，重试复用已认证挑战。各页完成校验与后台解码后立即展示，补页继续独立推进；来源失效时保留已取得的有效页。

重试向同一报告补齐缺页，重新申请会取得新的报告来源；完整旧报告继续展示期间保留新报告已下载的分页与来源，补页沿新报告继续推进。旧报告与新分页共用存活位图预算，预算需要时切换到已校验的新报告分页。验证码续接由页面模型持有，页面退出时取消下载。图片保留原始页码，由页面内存持有并按页数、传输、位图和整体等待预算验收。报告级认证或来源失效会及时结束余页下载，重试重新申请报告；网络诊断结合失败信息与完整页码集合判断可用性。

## 社区、消息与草稿

各社区场景分别维护首屏、分页、搜索和刷新代际。源页推进与去重状态分开记录，重叠页在当前任务内继续请求，最终统一发布游标；持续停滞进入可重试状态。刷新期间保留已有内容与游标，成功响应提交新的首屏状态。

话题与文章、成绩与课程分别通过系统 TabView 保留页面。切换分区保留列表、排序和滚动位置，页面沿离开和返回生命周期暂停、恢复所属请求。

课程、话廊与文章的详情、评论和编辑由所属功能服务承接。详情与评论请求各自完成时更新所属状态。话题详情复入保留已加载评论及交互确认，内容筛选变化在现有状态上更新可见内容；评论区域提供独立重试，联网与回到前台处理失败读取。

社区详情与卡片通过账号内共享计数流同步已确认的点赞、评论及课程评分。列表读取分别按点赞数、评论数及评分的字段修订合并后续交互，一次列表响应批量发布指标，各页面按对象标识合并；确认记录保留至相关在途读取完成，卡片原位更新并保留现有排序、分页和阅读位置。刷新失败或取消时恢复原有分页与加载状态，期间确认的新计数继续保留；评论写入沿实际统计响应更新，待恢复来源继续保留可用列表。

课程搜索在加载和失败期间保留输入区域，列表、详情和历史成绩在联网及回到前台时恢复失败读取。

课程和文章复用公共加载状态。文章列表与搜索共用集合的刷新、分页、取消恢复和预览生命周期，各页面持有独立集合与查询条件。课程列表支持原生下拉刷新；文章列表与搜索的原生刷新回调等待页面持有的刷新任务，页面离开时由所属模型结束请求。

用户、头像和身份标签的解码保留必要标识，附加展示字段缺失时继续展示可用内容；身份标签沿公共组件呈现。

帖子列表保留资源身份与匿名状态，日期、标签等展示字段按可用内容恢复。公开作者保留有效用户编号，异常身份及计数沿对应记录路径进入响应诊断。图片数组逐项恢复有效资源，异常项沿原响应记录诊断。列表正文驻留沿预览字节预算控制，完整正文由详情请求承接；长时间翻页继续保留全部记录标识与分页位置。

跨页面共享的评论呈现和正文链接归 CommunityUI，领域分页与草稿合同归 CommunityCore。

详情评论保留首屏刷新与分页的失败标记，连接恢复、重新进入或回到前台后沿共享状态重试对应请求；已有评论和已确认交互持续可读。

长帖与长评论提供原生全文阅读，正文预览和链接扫描继续受展示预算约束。文章富文本逐块准备并响应取消，结构异常的块保留完整原文入口及相邻有效正文。

文章内容解析、上传、创建及编辑均核对页面和账号生命周期。文章与帖子编辑通过取消入口确认待保存的修改。文章保存失败后重新读取远端内容，内容相符时确认成功；版本冲突时保留输入，并提供查看最新文章与明确确认覆盖的入口。待确认发布可直接进入带入标题的原生搜索，返回时保留编辑输入。

评论发送结果待确认时保留完整提交范围，用户核对列表并确认后可再次发送对应评论。

文章列表与搜索刷新期间保留当前结果和作者信息，首屏成功后交接预览代际并重新确认可见作者资料；文章版本变化或缺少更新时间时清理对应预览。作者昵称与头像的刷新沿列表读取生命周期执行，独立于正文版本。

文章预取按账号、代际和登录状态保留详情，凭据续期后继续复用同账号内容。详情请求共用四个名额，其中一个供主动阅读；详情打开时先展示预取内容，再重新确认服务器正文和交互状态，读取失败时保留可用内容。

账号资料由可注入的状态模型维护。昵称、签名与头像提交成功后先合并已确认字段，再独立刷新服务器资料；读取故障保留已确认值。首次读取失败提供原位重试，登录检查成功后重新读取资料。图片上传共用资源标识约束，传输错误保留底层原因。

创建、状态切换与更新由业务调用方声明结果语义，通用请求客户端沿声明判断发送结果。帖子更新的响应丢失后读回目标内容，字段全部相符时确认保存，结果继续待确认时保留编辑并引导核对。

应用中的可选鉴权读取遇到会话过期时，先尝试公开内容，凭据恢复由所属会话在后台合并推进；公开访问受限时等待同一次认证恢复再读取。退出、切换账号与清理登录数据会结束所属恢复任务，读取全过程继续核对账号代际。响应保留查看者认证来源，公开内容沿其来源保存缓存，点赞操作等待认证后的读取结果。

课程共享资料入口独立于历史成绩状态，已有历史图在刷新和错误期间继续展示。帖子及文章详情的下拉刷新共同触发媒体重试代际。

话廊网页后续加载或凭据同步失败时保留当前文档、输入和滚动位置，原生提示提供继续阅读与重试。重试定位失败的受信任地址；首屏加载失败及网页进程结束时提供重试页面。

消息中心先提供历史首屏，历史分页与未读窗口保存和服务端确认分别推进。摘要端点或本地已读文件受阻时，消息正文继续可读，角标与确认状态分别保留恢复信息。历史分页使用实际末条 ID。确认期间的新首屏与已浏览历史分别保存续读游标，新增区间补齐后继续读取原有历史；服务端分类清零通过独立确认请求执行，保存与恢复游标共同保护请求期间新到达的消息。

已读快照位于账号目录的 `message-read-snapshot.json`，读取验收格式版本与必要字段，通过受保护的原子写入提交。已读历史按分类保留 1024 项，显式未读候选与确认恢复游标独立保存。“全部已读”推进当前分类的历史已读边界，后台随后补齐的旧消息沿该边界处理。实例变更按账号发布，外部写入和账号切换使查询缓存失效。

发帖、文章和建议复用账号草稿存储与串行写入事务，元数据由各自快照组装。文章通过暂存和恢复保留输入，所属文章及新建内容汇集于固定的 `composer-paper.json`；编辑版本随草稿保留，发布清理核对所属账号与记录版本。文章条目独立读取和保存，损坏条目保留在原归档中，有效草稿继续使用。编辑页可管理当前账号的可读取草稿，确认删除时核对原条目版本，当前编辑输入继续保留。用户确认恢复存储后保留有效条目并清理损坏内容，当前页面输入继续保留。恢复动作捕获所属账号，并在执行前核对当前账号。文件访问问题与较新格式版本继续保护原文。

发帖与评论共用图片草稿、上传状态、重试和移除。图片读取及准备完成后进入本地草稿，上传按图片身份持有，取消后保留字节并提供重试；发帖保存等待本地导入完成，失败图片继续保留原始选择。上传成功的资源标识随元数据保存，恢复草稿继续复用已有上传结果。图片草稿的元数据与资产分开保存，单张图片预算为 1 MiB，最多九张。读取结果区分缺值、完整恢复、图片局部恢复、元数据读取问题和格式版本差异。单张图片缺失或超限时先恢复文字与其他图片，并提示重新选择；原始内容保持至后续保存或明确放弃。

文字暂存比较现有图片名称与实际字节，复用相同资产版本；图片内容或顺序变化后提交新资产与元数据，再清理旧版本。支持的历史快照在有效保存完成后迁入所属账号路径。提交清理捕获原账号和元数据版本，后续编辑的新草稿继续保留。

日程、DDL、课程和举报编辑器按当前输入保护下滑关闭，取消操作确认放弃。举报提交期间保护已捕获的输入，原弹层等待回执。

帖子和文章在创建请求前，将所属账号与提交内容原子写入固定的 `composer-publications.json`。记录独立于草稿，重启和恢复草稿后继续要求核对待确认的发布结果。用户查看自己的帖子或文章并明确确认后，可继续发布；记录读取受阻时，通过核对当前账号的帖子与文章重建记录，保留编辑内容和草稿。请求发送前的账号变化释放所属未发送记录，已发送请求的状态随原账号保留。

发帖、文章或建议取得成功回执后，所属任务清理已提交草稿及发布记录，页面完成退出和列表更新。帖子更新与删除通过目的地回调通知来源列表，帖子编辑和草稿恢复保留已选声明。清理问题保留原草稿及诊断。建议响应丢失时保留完整载荷，重试复用已捕获的提交身份。

## 网络边界

`HTTPTransport` 与 `HTTPClient` 提供统一传输、观察和错误映射。URLSession 由所属传输实例持有，连接池在 App 选择 Cookie、缓存、重定向、连接等待及期限策略。最后一个客户端释放传输后结束在途请求并关闭会话，Cookie 容器切换沿同一资源生命周期处理。

| 会话 | 边界 |
| --- | --- |
| 社区 | 共享所属账号的 Cookie、缓存与连接池 |
| 普通成绩与可信成绩单认证 | 共用认证传输，各自持有业务 challenge |
| 敏感下载 | ephemeral 配置，正文由当前页面持有 |
| 学校 CAS | 按业务选择手动重定向与 HTTPS 升级策略 |
| 教学中心及课程中心 | 独立会话、可失效认证状态和短信续接 |

社区认证失败由统一恢复策略协调续期与重放。凭据遭拒时暂停社区鉴权请求，保留本机账号、学校凭据与缓存阅读；账号登录使用 BIT101 密码，主动退出负责清理会话。连接问题保留当前会话。请求发送、恢复、解码与副作用提交继续核对登录代际。学校会话恢复、短信及有副作用的请求分别按所属协议处理重试。

社区删除接受目标端点返回的成功状态或 404，并继续校验最终请求方法与账号代际，支持响应丢失后的幂等重试。网络恢复观察进入已连接状态；消息页持有交互任务，分类切换与页面退出取消所属恢复，保留待续接的已读窗口。空教室刷新与选择查询共享任务所有权，选择变化取消旧查询，教学楼和查询日期在认证前捕获，学期沿学校当前响应确定。

连接池限制整体资源期限并保留更短的业务期限；持续响应受同一预算约束。响应聚合沿同一 URLSession 任务的系统数据块追加并检查取消，JSON 和媒体各有字节上限。错误正文按解析与展示预算处理，结构化错误和简短纯文本承接提示，HTML 与未知结构沿 HTTP 状态呈现。协议声明的资源缺失映射为所属服务类型，通用路由错误保留 HTTP 状态与原始说明。

`NetworkPathState` 提供实例级连接快照和连接恢复事件，页面处理所属业务重试，共享媒体环境处理图片恢复。网络提示沿既有队列异步呈现并保留冷却窗口，请求持续执行。诊断在固定容量中兼顾近期请求、故障与相邻上下文，并按账号代际隔离；业务状态与响应解析失败回写对应请求记录，响应解码保留字段路径和底层原因。传输中断和响应超限保留已收到的状态、响应头、容量受限的正文及最终请求，原始错误继续传播。学校服务恢复入口优先采用最终页面；两端地址共用报告脱敏与容量规则。

社区读取场景共用网络恢复、前台激活和重新进入页面的触发合同。场景按可见性与当前路由控制恢复，重试所属失败读取；查询与分页沿各自状态机续接，页面离开后取消所属任务。帖子空态与内容共用滚动容器，成功空列表继续提供下拉刷新。

社区登录优先调用 `/user/login`，账号缺失与密码错误的合并响应进入学校身份补充验证，并通过 `login_mode: true` 保留已有社区密码。社区密码摘要与学校密码分开存入 Keychain；社区密码验证成功后更新摘要，已有学校密码继续复用；学校凭据缺失时将本次登录密码作为首次认证候选，CAS 明确拒绝后共享一次学校密码输入。旧会话恢复先尝试已有凭据的社区登录，学校证明路径承接凭据差异。

首次建立本机账号遇到社区服务故障时，复用已有学校密码或本次登录输入，在独立 Cookie 容器中完成 CAS 与所需短信验证；学校明确拒绝密码后再弹窗收集替换密码。验证复用学校认证队列和表单协议，省略 action 的登录表单沿当前文档地址提交并保留 service 参数，取得学校签发的指定 service 票据后完成身份确认。Keychain 保存学校已验证状态及凭据，学校功能、Widget、Watch、提醒、实时活动和装机就绪沿有效本机会话判断；社区会话由其实际认证结果建立。学校独立登录的有效会话可在社区功能请求时按账号代际合并认证恢复；公开读取先返回已有结果，再启动后台恢复。凭据遭明确拒绝后保留用户重新认证入口。故障期间保留本机账号。切换账号与取消会结束验证，所属身份核对完成后才保存账号并交接学校 Cookie。已有可用本机账号继续沿当前恢复策略处理社区故障。

学校密码与原生短信输入共用提示退场等待，取消时清理敏感输入并结束所属等待。

学校服务优先复用本机 CAS 票据，教学中心、教务成绩与可信成绩单分别建立学校业务会话；教学中心以实际查询的“我的课表”应用建立会话，校外路线在本机登记 WebVPN 指纹、提交学校风控令牌并完成 service 回调。业务 Cookie 按所属域和路径传递，登录代际沿认证、下载和结果提交持续核对。成绩 HTML 直接映射学校表头，简略和详细查询共享本机认证，可信成绩单沿既有分页预算下载。学校本机路线的传输、会话及协议故障进入有界 bit-login 回退，取消与凭据输入错误交由所属交互处理。乐学优先直连学校，WebVPN 由本机认证承接。

学校协议适配层为认证限制、账号锁定、会话失效和资源访问限制保留类型化错误来源，CAS 页面和中转错误共用账号锁定识别。账号锁定在密码更正与中转恢复前结束当前认证，提示明确说明账号状态；认证受限与账号锁定提供学校统一认证入口，服务故障保留学校服务检查入口。提示模型与页面失败状态沿同一错误链和操作文案呈现。已发布客户端的响应标记继续由报告受理端核对，这些异常在正式报告配额预留和写入前结束上报；客户端解析、本地缓存及协议适配问题继续保留开发者诊断。学校请求失败时继续保留已有课表和本地编辑能力，会话恢复沿所属账号有界推进。

外部 BIT101 后端、Android 和 Web 项目属于只读参考及对应维护者的工作范围。iOS 保存请求与响应证据，负责协议适配、错误呈现和恢复。Cloudflare 自有 Worker、隐私页面和分享链接由本仓库维护，部署与发布沿明确授权执行。

## 存储与账号隔离

| 数据 | 位置与生命周期 |
| --- | --- |
| 学校凭据与社区会话凭据 | Keychain，按账号选择与安装状态维护 |
| Cookie、challenge、access token、短信状态 | 所属会话内存与 Cookie 容器，按账号及失效事件更新 |
| 主题、旋转、自动更新检查等设备偏好 | 应用级 UserDefaults |
| 账号设置、成绩筛选与消息已读 | 账号级偏好或所属业务仓库 |
| 日程、成绩与草稿 | 账号隔离的 Application Support 文件 |
| 可重建图片与头像 | 系统 Caches，按容量和近期访问回收 |
| Widget 与 Watch 展示 | App Group 中的精简快照及版本边界 |

`AppFileService` 统一文件内容、目录、元数据、保护和规范路径操作。生产读取先验收容量，再读取有界字节；写入准备所属目录并使用受保护的原子提交。用户持久目录参与系统备份，历史备份元数据在场景启动后完成一次迁移，日常写入维护所属目录的策略；可重建缓存和临时展示沿各自生命周期清理。

`AccountScopedCodableStore` 统一偏好键、迁移、编码和扩展字段保留。读取区分缺值、有效值与损坏值；未知格式保留原数据并暂停对应保存与云同步。账号设置与成绩筛选提供独立恢复入口，确认后恢复当前账号快照并重建所属同步域的派生合并基线，日程、成绩、登录及设备偏好保持所属生命周期。

本地数据清理通过 App 组装的资源所有者执行，覆盖偏好、凭据、文件、Cookie、URLCache、媒体和共享快照。清理前等待已接收的存储操作结束，异常按资源保留诊断。社区线上写入的待恢复事务先完成对应恢复，再按账号范围处理本机清理。

## iCloud 同步

课表通过 CloudKit 同步用户状态，App 负责容器、记录和 system fields 适配；学校正文由本机学校同步持有。同步状态机维护拉取、合并、冲突选择和推送的互斥关系，并在启动、前台恢复和账号切换后沿所属生命周期运行。

手动 DDL 的图片压缩后随本机记录保存，每条最多九张、单张 1 MiB、全部附件共 16 MiB。CloudKit 将普通 JSON 元数据与 `ddlImagesAsset` 资产分开存储，拉取时按 DDL 稳定 ID 还原图片；普通字段沿用 1 MB 预算，含附件的本机缓存上限为 64 MiB。资产写入串行复用固定暂存路径，并在提交后释放。

本机持久化保存已确认的用户状态作为三方合并基线。独立记录按稳定 ID 合并，相对基线的删除继续传播，顺序和同一字段的并发分歧进入冲突决策。比较写入核对磁盘版本和云端基线，保存期间的新编辑继续保留待同步状态。

成绩 KVS 同步使用加密载荷，密钥由 iCloud 钥匙串协作。实验性偏好同步分别管理设置、筛选和已读业务域；字段修改、可选值清除和已读并集按所属版本合并。账号事件、保存通知和同步实例显式注入，业务存储成功后推进对应云版本。

校园地图按页面可见性和场景活跃状态管理定位；页面退出时释放待完成的定位请求。下一节课扫描保留最近候选，再准备地点与时间展示。

## 媒体与设计系统

通用颜色、字体、间距、页面状态、刷新行、编辑器、标签、评论和原生交互组件归 DesignSystemKit。社区共享展示归 CommunityUI，功能页面消费公共组件并持有实际业务动作。详细界面约定见 [设计系统](DESIGN_SYSTEM.md)。

媒体环境注入传输、图片文件服务、预览文件服务和容量协调器。`CommunityImage` 统一验收 HTTP(S) 图片地址，媒体入口将 HTTP 升级为 HTTPS，缓存与在途请求沿安全地址合并。头像、列表静态图和详情优先读取已有原图及低清缓存；下载按低清与原图地址恢复，低清故障时继续尝试原图。列表和详情静态图共用加载器，详情在低清展示后继续准备原图。

照片读取在系统提供者的有效期内按预算完成，压缩和静态、动画解码在后台执行；图片、头像和预览共用原始字节及位图预算。DDL 与社区草稿共用逐张导入流程，单张失败后继续处理其余图片，任务取消与所有者变化时结束导入。草稿缩略图按预览数据与显示比例在后台准备，编辑界面重绘复用已准备的位图。动图原文件就绪前保留静态预览，原图加载失败后继续展示可用图片。

图片缓存写入故障时，有效字节进入受容量约束的内存缓存并继续显示；旧文件清理沿后台存储执行器完成。

Quick Look 使用明确准备的本地 URL，来源视图结束时关闭预览并释放资源。启用系统“减弱动态效果”时，渐进换图直接更新。

活跃预览文件由所有权登记保护，文件创建、登记、回收和清理共享同一资源边界。本地图片和成绩单的系统预览文件写入受保护的临时目录，预览结束释放，启动时回收残留。预览关闭沿已登记的配额条目清理，目录扫描按既有周期与显式清理执行。

Quick Look 独立以模态展示，由系统管理分页与工具栏；优先展示缓存，缓存缺失时立即提供原生加载与关闭控件。低清和原图在预览内并行准备，可用资源就绪后原位展示。共享媒体环境在联网和回到前台时恢复失败图片。静态位图、头像与 GIF 共用展示预算管理，文件读取与解码使用独立执行器，内存压力释放可回收预算，等待中的视图在预算可用时继续加载。

话廊与头像按 URL 共享原始图片字节、下载任务、磁盘文件和资源租约，位图解码沿所属展示预算复用。磁盘图片首次或到期扫描建立容量与访问时间库存，写入按条目更新容量并执行回收，显式策略变更和清理更新库存。回收跳过活跃展示文件，按近期访问顺序释放可重建内容。文件工作在独立执行器进行，主线程维护界面会话。

## Widget、Watch 与 Live Activity

App 将当前账号日程转换为精简共享快照，包含课程、个人日程与 DDL 的扩展展示字段。DDL 摘要提供空标题显示值，按共享字段的 UTF-8 预算截取文字，身份或日期异常的记录独立过滤。共享身份、修订与时间线规则归 ScheduleContracts，磁盘协调归 ScheduleSharedStore。Widget、Watch App 和 Watch Widget 分别消费相同的业务合同。

个人日程按重复日期展开，与课程按开始时间合并；个人日程独立于学期首日。DDL 时间线复用一次排序，围绕当前可见条目生成刷新节点，窗口推进后继续请求下一批。

共享快照读写在后台执行，账号切换和退出清空所属展示。凭据读取待恢复时保留已发布课表、提醒与活动，读取恢复后按账号代际继续同步；装机就绪随登录呈现和凭据恢复重新核对。Watch 前台重读受限时保留已确认快照，在后台按当前时间重算课程并显示缓存提示；快照变更、退出与成功清理执行所属内容失效。Watch 清理保存精简版本边界，重启后继续拒绝迟到旧传输，新版本到达后恢复。请求、回复和持久化共同核对最高已接受修订，断线后支持前台再次请求。

日历导入、提醒和 Live Activity 由 App 平台适配器消费课程及账号上下文。日历事务串行维护展开、写入与回滚，通知替换保留失败恢复边界；权限返回后再次核对账号。ActivityKit 属性独立于纯领域合同，系统界面与投递沿真机专项验收。

系统日历事件保存所属账号、学期及日程标记，链接回到对应课表详情。地点对象以完整教室文本作为标题，已匹配的校园建筑提供校准坐标；其余地点保留文本。完整地点文本供系统日历及锁屏组件读取。导入索引受损时，课表设置提供确认后的重建入口，从系统日历中近十年与未来十年的当前账号标记恢复批次，保留事件内容。批次按学期和日历归属维护，增量导入保留各日历中的其余事件；删除沿已记录日历的标记重新定位同步后改变标识的事件。

## 服务边界门禁

静态审计复用当前工具链的 SwiftSyntax 事实，核对依赖方向、资源归属、公开能力、自动学校请求、设计系统和测试登记。基础传输、媒体与平台资源按明确签名归属，新增业务能力进入对应网络和交互库存。

原生构建验收 Swift 类型、隔离与平台编译语义，行为测试验收状态、取消、失败恢复和持久化，UI 与人工专项验收真实控件及系统能力。检查器作者提供触发、合规和故障样例，较大源码按生命周期和职责审查，维护文件统一遵守 1000 行上限。

验证输入使用提交、环境和实际内容身份关联结果。编译缓存、工具链选择、测试库存、原始结果及发布证据由既有脚本维护；开发时选择受影响分组，检查器自测由统一审计集中执行。工作流命令、固定产物和 CI 范围统一见 [构建与测试](TESTING.md)。

## 开发与验证基础设施

### 输入与结果复用

编译验收覆盖完整产品输入。网络与 iCloud 的已完成采样沿生产能力及其模块依赖绑定，壳层组装、资源、manifest 和所属脚本共同参与输入；独立模块的改动按实际依赖决定专项复验。静态审计实现沿审计流程验收，网络与 iCloud 业务采样绑定采集实现及协议合同，现有请求与响应继续接受当前规则校验。完整行为组与 UI 组沿同一固定结果路径事务合并，各组保留自己的原始执行身份与性能采样。定向回归保留有效完整验收包，并覆盖 `diagnostics/test-results.xcresult` 中的当前诊断；完整验收继续使用 `test-results.xcresult`。报告、活动记录与截图按原始结果的写入时间选择当前包，元素树与崩溃日志汇集到同一份带来源说明的诊断文本。覆盖率按平台的实际可执行源码验收，账号切换、取消、存储故障和内容恢复由关键合同逐例检查。

本地验证直接比较所属文件内容、执行权限和环境，相同内容在提交前后沿用身份。共享证据以稳定的匿名身份交换本机路径与设备标识。已提交输入按 Git 第一父提交链读取相关差异，合并提交纳入相对第一父提交的改动；所属组与 Worker 共用这一身份口径，范围外改动保留相关结果。公开发布回执核对已提交输入和工具链。大型文件等维护候选保存在固定代码质量报告中，按需打开审阅。

### 原始结果与批次

同类日志、截图和报告覆盖固定路径。`test-metrics.txt` 保存构建与运行耗时、逐例结果、最慢用例、进程及交互统计。`report json` 和 `report coverage` 沿当前批次读取模块事件及模块覆盖率，或原生结果包。报告按指标和结果包的完成顺序选择当前来源；新构建结果优先于旧测试指标，构建诊断沿所属结果包呈现。

模块测试失败时同样生成当前批次指标，`report` 与 `report json` 呈现本次失败和模块日志；事件采集失败会说明原因。模块覆盖率沿成功执行生成。

原生结果保存到固定结果包，中断时恢复前序结果。相邻完整测试组共同汇总，同组再次完整执行时开启新批次；`verify` 从首组开始组织完整验收批次。定向复验保留相同输入和环境下的完整结果，发布验收核对采样时效。性能采样按所属输入和工作负载复用。

输入变化、相关失败或证据过期时，所属完整组进入重新验收。模块测试及诊断整理保留当前原始失败包，新的结果生产流程覆盖所属诊断。CI 汇总完成后清理远端缓存，并上传构建失败的原始诊断包。

### 公共缓存与工作流资源

缓存维护保留增量编译所需文件，共享 SDK、模块、原生 CompilationCache 和索引，保留当前产物与测试宿主的配套符号；孤立符号按产物生命周期回收。成功编译后按 CAS 分配空间或磁盘可用空间的累计变化触发维护，采样步长为 64 MiB；首次编译建立采样。原生维护在独立子进程中执行，每个原生存储按 2 GiB 的容量目标管理当前代与上游代，由工具链回收历史代。子进程失败沿诊断提示重试，构建保留自身执行结果。并行构建结束时由取得写锁的入口完成回收。构建数据库保留增量依赖记录，空闲页达到采样步长且磁盘具备整理空间时，使用 SQLite VACUUM 回收空页。固定报告 `.build/compiler-cache/compilation-cache.json` 在维护完成后重新采样，在 `space` 字段保存项目、CAS、SDK、模块、索引、构建及诊断占用；根层的 `identity`、`flavor` 记录 CI 传输身份，构建分类涵盖网络与 iCloud 专项产物。完整静态审计沿相同增长条件维护缓存并更新空间采样。隐式 PCM 由工具链维护生命周期，显式 SDK PCM 按完整依赖映射回收。远端缓存按来源提交与工具链选择，恢复失败后沿当前源码编译。缓存与诊断保持原始形式，CI 产物使用零压缩传输。

构建与静态条件求值共享编译缓存的读锁；已有缓存布局沿共享锁直接进入构建，目录初始化、迁移和回收持有写锁。中断工作流时先归集当前用户的子进程所属的进程组，完成后台任务清理后释放工作流锁。

App 与扩展沿 Release 编译配置验收，XCTest 和 UI 测试包采用增量编译，定向修复复用其他测试文件的编译产物。

工作流先取得工作副本产物锁，再取得用户级共享资源锁。模块与 Catalyst 测试的固定系统偏好沿共享锁串行验收；聚合流程继承锁、设备及总时钟。网络采样和反馈读取采用通用终端输出预算，长报告显示首尾内容及完整报告路径。

聚合验收的首个 XCTest 组沿完整验收入口保留可复用的其他组原始结果，后续组继续合并到同一结果包。

CI 的行为库存选择数字型号 iPhone 的最新运行时与最新标准机型，并复用相同设备类型。UI 交互在本地真机验收，CI 配置检查器拒绝 UI 测试入口及包含 UI 的默认全量测试命令。

超时和取消沿整个工作流进程组回收后台工作，设备及产物锁覆盖恢复与回收过程。工作流自然或失败退出时，所属进程组的遗留工作完成回收并登记失败；监督器异常退出沿同一回收路径处理。审计 worker 提前结束时同样核对所属进程组。远端缓存按 HTTP 分段流式接收，状态、范围及长度在所属分段中校验，整次下载共用五分钟期限。

### 静态事实缓存

SwiftSyntax 事实保存在固定 SQLite 数据库中，跨审计复用。原始源码与各编译条件库存使用独立上下文，正文相同的文件共用原始事实。语法文本通过 UTF-8 字节区间引用共享源文件，调用清单按调用节点编号还原，语义字段保留编译器表示。索引器源码、工具链和交互规则共同决定缓存版本；版本变化后重建事实并回收旧存储页，源码按实际内容更新，已删除文件的条目同步回收。

并行检查按文件读取事实，各次请求持有独立对象。测试继承按当前请求的文件集合解析，别名展开等变换内容独立解析。

### CI 结果归集

候选从 main 分支的手动验收历史分页读取，各组通过完整验收后生成独立结果记录，复用时核对来源提交、运行、输入差异、实际 Xcode、编译器、SDK 和宿主系统。

App 行为与正式组装结果核对 iOS 模拟器的系统版本与构建号，并以完整库存及覆盖率归集的结果为依据。模拟器成功记录沿独立字段保存；发布流程核对本地真机生成的 UI 验收证据。

CI 归集核对行为测试的全部用例、参数实例、来源提交、实际设备和合并覆盖率。
